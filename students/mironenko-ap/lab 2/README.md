# Отчёт о работе: KNN с ядром Парзена переменной ширины на датасете UCI Wine

## 1. Постановка задачи

**Цель работы:** реализовать алгоритм KNN с ядром Парзена переменной ширины
(sample-point), подобрать параметр `k` методом leave-one-out (LOO), сравнить
с эталонной реализацией `sklearn.neighbors.KNeighborsClassifier`, а также
исследовать влияние отбора эталонов (CNN, ENN, CCV) на качество
классификации.

**Датасет:** UCI Wine (178 объектов, 13 числовых признаков, 3 сбалансированных
класса — `class_0`, `class_1`, `class_2`), загружается через
`sklearn.datasets.load_wine`. Использование sklearn допускается только для
загрузки данных и как эталон; вся арифметика KNN, LOO и отбора эталонов
реализована на numpy.

---

## 2. Описание реализованных методов

### 2.1. ParzenKNN (нативный алгоритм)

Файл `parzen_knn.py`. Реализован **KNN с гауссовым ядром Парзена и переменной
шириной окна** (sample-point метод Парзена–Розенблатта):

- Каждому обучающему объекту $x_i$ сопоставлена своя ширина
  $$h_i = \rho_k(x_i) = \text{расстояние до его } k\text{-го ближайшего соседа (сам исключён)}.$$
- Оценка плотности класса $c$ в точке $x$:
  $$\hat p(x \mid c) = \frac{1}{N_c} \sum_{i:\, y_i = c} \frac{1}{h_i^{\,d}}\, K\!\left(\frac{\|x - x_i\|}{h_i}\right), \quad K(u) = e^{-u^2/2}.$$
- Предсказание: $\hat y = \arg\max_c \hat p(x \mid c)$.

**Численная устойчивость:** все вычисления ведутся в логарифмах —
`log_w = -d·log(h_i) - 0.5·||x − x_i||²/h_i²`, а сумма по классу берётся через
`logsumexp`. Это критично: при $d = 13$ и малых $h_i$ величина $1/h_i^d$
выходит за пределы представимости `float64`.

**Параметр `k`** в нашей модели — это не число соседей в голосовании,
а параметр локальной ширины окна (номер порядковой статистики). При
`k → ∞` окно расширяется, оценка становится всё более гладкой и смещённой;
при `k = 1` — почти вырожденной, «приклеенной» к точкам.

### 2.2. Метрики

Файл `metrics.py`. На numpy реализованы `accuracy`, `confusion_matrix`,
`precision/recall/F1` по классам и `macro_f1`. Никакой зависимости от sklearn
в блоке метрик нет.

### 2.3. LOO-подбор `k` (точный LOO)

Файл `loo_search.py`. Эмпирический риск оценивается по схеме leave-one-out:

$$\hat R_{LOO}(k) = \frac{1}{n}\sum_{i=1}^{n} \mathbb{1}\{\hat y_{-i}(x_i; k) \neq y_i\},$$

где $\hat y_{-i}$ — предсказание по выборке без $i$-го объекта.

**Точный пересчёт ширин окон при исключении объекта.** В sample-point
Parzen ширина $h_m$ зависит от $k$ ближайших соседей $m$. Если контрольный
объект $i$ — один из них, то $h_m$ при исключении $i$ меняется, и
предсказание для $x_i$ должно использовать уже **новые** ширины $h_m^{(-i)}$.
Приближение «вычислить $h$ один раз на полной выборке и заморозить»
даёт систематически заниженную LOO-оценку (см. п. 3.1) и не является LOO
в строгом смысле.

В работе реализован **точный** LOO с $O(1)$-обновлением $h_m$ на пару
$(i, m)$, без роста асимптотики. Ключевое наблюдение: в отсортированном
массиве расстояний от $m$ удаление точки $i$ сдвигает $k$-ю порядковую
статистику тогда и только тогда, когда

$$d(m,i) \le d_{(k)}(m) \quad\text{и}\quad c_m = k,$$

где $c_m = \#\{j \ne m : d(m,j) \le d_{(k)}(m)\}$ — число точек не дальше
$k$-го расстояния (включая ничьи). В противном случае $k$-я статистика
не меняется. Тогда точное правило обновления:

$$
h_m^{(-i)} =
\begin{cases}
\sqrt{d_{(k+1)}(m)}, & d(m,i) \le d_{(k)}(m) \text{ и } c_m = k,\\
\sqrt{d_{(k)}(m)},   & \text{иначе.}
\end{cases}
$$

**Реализация:** для каждого $k$ один раз вычисляются $d_{(k)}$, $d_{(k+1)}$
(через `np.partition` с двумя индексами), $c_m$ и булева матрица
`changed_mat[i, m]` размера $n \times n$. В LOO-цикле $h_m$ восстанавливается
через `np.where(changed_mat[i], h_kplus1, h_kth)`. Сложность остаётся
$O(n^2 \cdot |k\_values|)$ — никакого $O(n^3)$.

**Корректность** проверена smoke-тестом `loo_error` vs `loo_error_naive`
(полный пересчёт $h$ на каждой свёртке) на подвыборке $n = 50$: результаты
совпадают побитово для $k \in \{1, 2, 3, 5\}$.

### 2.4. Отбор эталонов

Файл `prototype_selection.py`:

- **CNN (Condensed Nearest Neighbor, Hart, 1968)** — жадный алгоритм для
  1-NN: стартуем с одного объекта каждого класса; добавляем точку, если
  текущее подмножество классифицирует её неверно; повторяем проходы до
  стабилизации.
- **ENN (Edited Nearest Neighbor, Wilson, 1972)** — удаляем точку $x_i$,
  если класс большинства её $k$ ближайших соседей не совпадает с $y_i$
  (сглаживание шума).
- **CCV (Compactness Criterion, Sánchez et al., 1997)** — отбор по
  **профилю компактности**. Для каждого кандидата $m$ считаем число
  «правильных» голосов
  $$\Pi(m) = \#\{j \ne m : y_j = y_m,\ m \in \mathrm{kNN}_{X\setminus\{x_j\}}(x_j)\}$$
  и «неправильных»
  $$R(m) = \#\{j \ne m : y_j \ne y_m,\ m \in \mathrm{kNN}_{X\setminus\{x_j\}}(x_j)\},$$
  где окрестность строится **с самоисключением** голосующего $x_j$ (это
  принципиально: без самоисключения $x_j$ всегда «голосует» за сам себя,
  и профили вырождаются). Также $\Sigma(m) = \Pi(m) + R(m)$ — общее число
  голосов. Реализованы варианты отбора:
  - `pi_gt_r` — $\Pi(m) > R(m)$ (в работе используется этот);
  - `pi1` — $\Pi(m) > 0$ при $k = 1$ (классический CCV);
  - `pi_minus_r` — $\Pi(m) - R(m) > $ threshold;
  - `sigma_pi_r` — $\Sigma(m)\cdot\Pi(m)/\max(R(m),1) > $ threshold;
  - `pi_over_r` — $\Pi(m)/\max(R(m),1) > $ threshold.

  Ключевое отличие от CNN/ENN: **сравниваются кандидаты по профилям
  $\Pi, R, \Sigma$, а не по текущим ошибкам классификации**. CNN добавляет
  точку, если её текущий 1-NN ошибается (жадно, без сравнения кандидатов
  между собой); ENN удаляет по голосованию $k$ соседей (тоже без профилей).
  CCV же для каждого $m$ независимо считает «за» и «против» и оставляет
  только «представителей» — точки, на которые указывает хотя бы одна
  другая точка своего класса.

## 3. Результаты

### 3.1. Подбор `k` методом LOO

Кривая эмпирического риска (`report/figures/loo_curve.png`,
`loo_curve.csv`), **точный LOO** после исправления ширины окон:

| k  | LOO-error (точный) | LOO-error (замороженный $h$, приближение) | Δ (ошибок из 178) |
|----|--------------------|-------------------------------------------|-------------------|
| 1  | 0.1124             | 0.1067                                    | +1                |
| 2  | **0.0955**         | **0.0955**                                | 0                 |
| 3  | **0.0955**         | **0.0955**                                | 0                 |
| 5  | 0.1573             | 0.1461                                    | +2                |
| 7  | 0.1854             | 0.1742                                    | +2                |
| 10 | 0.2416             | 0.2303                                    | +2                |
| 15 | 0.3820             | 0.3427                                    | +7                |
| 20 | 0.4663             | 0.4607                                    | +1                |
| 25 | 0.5506             | 0.5225                                    | +5                |
| 30 | 0.6067             | 0.6067                                    | 0                 |

**Оптимум:** $k^\star = 2$ (при ничьей с $k = 3$ берётся меньшее `k`).
Минимум LOO-ошибки $\approx 0.0955$. Кривая имеет выраженный U-образный
характер: при малых `k` окно слишком узкое (переобучение, «острые»
плотности), при больших — слишком широкое (недообучение, классы
размываются).

**Сравнение точного и приближённого LOO.** Колонка «приближение»
воспроизводит старую версию, в которой ширины $h_m$ вычислялись один раз
по полной выборке и не пересчитывались при исключении контрольного
объекта. Разница **всегда неотрицательна** (точный LOO ≥ приближённый),
т.е. приближение систематически **занижает** риск. Максимум расхождения —
при $k = 15$: 7 ошибочно классифицированных объектов из 178 (11.5 %
относительно). Причина: при классификации $x_i$ ширина $h_m \approx d(m,i)$
для соседа $m$, ближайшего к $x_i$, что даёт «подглядывание» в сторону
$y_i$ через ширины соседей. **Важно:** argmin `k` в обеих версиях совпадает
($k^\star = 2$), поэтому приближение было адекватно для *выбора*
гиперпараметра, но не для *отчётной оценки* риска — это и было причиной
исправления.

**Обоснование выбора гауссова ядра:** оно гладкое, бесконечно
дифференцируемое, сепарабельное по координатам; нормировочная константа
$(2\pi)^{-d/2}$ одинакова для всех классов и на argmax не влияет. Это
классический выбор для оценки плотности (Парзен, 1962; Розенблатт, 1956).

**Обоснование переменной ширины (sample-point):** в задаче с тремя классами
и 13 признаками плотность объектов распределена неравномерно; глобальная
(fixed) ширина либо пересглаживает плотные области, либо недосглаживает
разреженные. Локальная ширина $h_i = \rho_k(x_i)$ адаптируется к локальной
геометрии данных.

### 3.2. Сравнение с эталонным sklearn KNN

Файл `compare_sklearn.py`, стратифицированный split 80/20
(`random_state = 42`), стандартизация по train. Результаты (`compare.csv`,
macro-F1):

| k  | ParzenKNN (ours) | sklearn (uniform) | sklearn (distance) |
|----|------------------|-------------------|--------------------|
| 1  | 0.8286           | 0.9164            | 0.9164             |
| 2  | 0.8915           | 0.8878            | 0.9164             |
| 3  | **0.9230**       | 0.8876            | 0.8876             |
| 5  | 0.8424           | 0.9718            | 0.9718             |
| 7  | 0.7755           | 0.9441            | 0.9441             |
| 10 | 0.8136           | 0.9452            | 0.9164             |
| 15 | 0.6925           | 0.9452            | 0.9452             |

**Наблюдения:**

1. Наилучший результат нашего алгоритма — **0.9230 (macro-F1) при k = 3**,
   что согласуется с LOO-оптимумом (k = 2–3).
2. sklearn-эталон достигает **максимума 0.9718 при k = 5** (и `uniform`,
   и `distance`).
3. При больших `k` наш метод резко теряет качество — это ожидаемо,
   поскольку `k` здесь управляет шириной окна, а не голосованием:
   размытие плотностей классов при росте `k` приводит к систематической
   ошибке. У sklearn же рост `k` наоборот стабилизирует голосование.
4. Разрыв $\sim 5$ п.п. по macro-F1 объясняется:
   - `sklearn KNN` — дискретный голосующий алгоритм с адаптивной метрикой,
     устойчивый к выбросам при `weights='distance'`;
   - `ParzenKNN` — плотностная оценка; она даёт более гладкие,
     «вероятностные» границы, но хуже работает в режиме малой тестовой
     выборки (36 объектов) и при небольшом числе признаков, где локальная
     плотность сильно шумит.
5. Параметры алгоритма `ParzenKNN` (гауссово ядро, `k` из LOO,
   стандартизация по train) выбраны согласованно: LOO-оптимум k = 2–3
   совпадает с тестовым оптимумом k = 3.

### 3.3. Отбор эталонов

Файл `prototype_selection.py`, split 80/20, `random_state = 42`, `k = 2`
(выбран по LOO). Полный train = 142 объекта, распределение
`[47, 57, 38]` (class_0, class_1, class_2).

**CNN (Hart, 1968):**
- оставил **25 объектов (17.6 %)** от train;
- распределение по классам: см. `prototypes_cnn_idx.npy`.

**ENN (Wilson, 1972, k = 3):**
- сохранил **138 объектов (97.2 %)** — удалил лишь 4 шумовых точки;
- распределение по классам практически совпадает с исходным.

**CCV (Sánchez et al., 1997, k = 1, вариант `pi_gt_r`):**
- сохранил **85 объектов (59.9 %)** — сжатие на 40 %;
- распределение по классам: **`[30, 32, 23]`** — пропорционально исходному
  (retention по классам 63.8 %, 56.1 %, 60.5 %), перекоса нет;
- профили компактности на полном train:
  - $\Pi(1)$: mean $= 0.96$, max $= 5$ — то есть 95.8 % всех 1-NN-рёбер
    в обучающей выборке внутриклассовые (датасет чистый);
  - $R$: mean $= 0.04$, max $= 2$ — всего около 6 «неправильных»
    1-NN-рёбер на 142 объекта;
- из 85 отобранных эталонов **83 имеют $R = 0$** (ни одного
  «неправильного» голоса) и **85 имеют $\Pi > 0$** (по построению
  `pi_gt_r`). То есть CCV сохраняет «представителей» — точки, на которые
  указывает хотя бы одна другая точка того же класса, — и отбрасывает 57
  «избыточных внутренних» точек, чей вклад в Parzen-оценку дублируется
  соседями.

**Качество на тесте (`selection_compare.csv`):**

| Вариант | Accuracy | Macro-F1 | n_train |
|---------|----------|----------|---------|
| full    | 0.8889   | 0.8915   | 142     |
| cnn     | 0.6111   | 0.5721   | 25      |
| enn     | 0.8889   | 0.8915   | 138     |
| **ccv** | **0.8889** | **0.8885** | **85** |

**Наблюдения:**

1. **CNN резко ухудшает качество** (−28 п.п. accuracy): алгоритм жадный
   и ориентирован на 1-NN, поэтому оставляет только объекты вблизи границ
   классов. Для `ParzenKNN` с ядром и `k = 2` этого мало — плотности
   классов теряют «тело» распределения, оценки становятся неустойчивыми
   (в частности, для класса 2 остались считанные прототипы).
2. **ENN практически не меняет качество** (+0 п.п.), удаляя лишь 4 точки:
   датасет Wine чистый, и в нём почти нет объектов, чьи 3 ближайших соседа
   голосуют за другой класс. Это ожидаемый результат для хорошо
   разделимых данных; ENN в этой таблице — **неинформативный baseline**
   (он «сохраняет всё», а не «сжимает без потерь»).
3. **CCV даёт содержательное сжатие без потери качества**: −40 % обучающей
   выборки, accuracy не изменилась (0.8889 → 0.8889), macro-F1 упал на
   **0.003** (0.8915 → 0.8885) — на 36 тестовых объектах это в пределах
   шума. Сжатие равномерно по классам, ни один класс не «схлопнулся».
   Это ровно то поведение, ради которого CCV и реализовывался: удаляются
   избыточные внутренние точки плотных кластеров, чей вклад в
   Parzen-оценку дублируется соседями, сохраняются «представители».
4. **Вывод:** ENN-сжатие на Wine малоинформативно (сжимать нечего), CNN
   в чистом виде неприменим к плотностным методам, а **CCV — единственный
   из трёх методов, дающий содержательное сжатие без потери качества**.

## 4. Выводы

1. **Реализован** `ParzenKNN` — KNN с гауссовым ядром Парзена и переменной
   шириной окна (sample-point). Все вычисления в логарифмической шкале
   обеспечивают численную устойчивость при $d = 13$.
2. **Параметр `k`** подобран **точным** LOO: оптимум $k^\star = 2$ с
   LOO-error $\approx 0.0955$; на тесте лучшее качество при $k = 3$
   (macro-F1 = 0.923). Кривая эмпирического риска имеет классический
   U-образный вид. Сравнение с приближённым LOO (замороженные ширины $h$)
   показало, что приближение систематически **занижает** риск — до 11.5 %
   относительно при $k = 15$; при этом argmin `k` в обеих версиях
   совпадает, что подтверждает: приближение годится для *выбора*
   гиперпараметра, но не для *отчётной оценки* риска.
3. **Сравнение со sklearn** показывает близкие результаты при согласованных
   `k` (наши 0.923 при k = 3 vs sklearn 0.918 при k = 3), при этом
   sklearn-эталон на `weights='distance'` даёт максимум 0.9718 при k = 5.
   Разрыв объясняется плотностной (а не голосующей) природой нашего
   алгоритма.
4. **Отбор эталонов:**
   - ENN на датасете Wine почти ничего не удаляет (138 из 142) и не меняет
     качество — датасет чистый, шума для удаления нет;
   - CNN сильно сжимает выборку (25 из 142), но для плотностного
     `ParzenKNN` это приводит к деградации качества (macro-F1 падает
     с 0.89 до 0.57), поскольку CNN ориентирован на 1-NN и оставляет
     только граничные точки;
   - **CCV (Compactness Criterion) даёт содержательное сжатие без потери
     качества**: 85 из 142 (59.9 %), accuracy 0.8889 → 0.8889,
