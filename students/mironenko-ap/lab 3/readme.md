## 1. Постановка задачи

Требовалось:

1. Выбрать датасет для бинарной классификации.
2. Реализовать решение двойственной задачи SVM по множителям Лагранжа $\lambda$.
3. Использовать `scipy.optimize.minimize` **или любую другую библиотеку** для оптимизации.
4. Применить **kernel trick**.
5. Построить линейный классификатор.
6. Визуализировать решение.
7. Сравнить с эталонной реализацией `sklearn.svm.SVC`.

В работе реализованы **оба варианта оптимизации**: собственный SMO на `numpy` и `scipy.optimize.minimize` (SLSQP). Прогон по умолчанию выполняет их последовательно, а также сравнивает линейное и RBF-ядра — чтобы явно показать как нелинейный случай (kernel trick), так и линейный классификатор в исходном пространстве.

## 3. Математическая постановка

### Прямая задача (soft-margin SVM)

$$
\min_{w,\, b,\, \xi}\ \frac{1}{2}\|w\|^2 + C\sum_{i=1}^{n}\xi_i
$$

при ограничениях

$$
y_i\bigl(w^{T}\varphi(x_i) + b\bigr) \ge 1 - \xi_i, \qquad \xi_i \ge 0, \quad i = 1,\dots,n.
$$

### Двойственная задача по $\lambda$

$$
\max_{\lambda}\ \sum_{i=1}^{n}\lambda_i - \frac{1}{2}\sum_{i=1}^{n}\sum_{j=1}^{n}\lambda_i\lambda_j\,y_i y_j\,K(x_i,x_j)
$$

при ограничениях

$$
0 \le \lambda_i \le C, \qquad \sum_{i=1}^{n}\lambda_i y_i = 0,
$$

где $K(x_i,x_j) = \langle \varphi(x_i), \varphi(x_j)\rangle_{\mathcal H}$ — функция ядра.

### Классификатор

Восстанавливается только через ядро, без явного $\varphi$:

$$
f(x) = \sum_{i=1}^{n}\lambda_i y_i\,K(x_i,x) + b, \qquad \hat y(x) = \operatorname{sign} f(x).
$$

### Реализованные ядра

| Ядро | Формула |
|---|---|
| Линейное | $K(x,y) = x^{T} y$ |
| RBF | $K(x,y) = \exp\!\bigl(-\gamma\,\|x - y\|^{2}\bigr)$ |
| Полиномиальное | $K(x,y) = \bigl(x^{T} y + c_0\bigr)^{d}$ |

По умолчанию $\gamma = \texttt{"scale"} = \dfrac{1}{n_{\text{features}}\cdot \mathrm{Var}(X)}$ — эвристика sklearn.

## 4. Реализация

### 4.1. Два решателя

`DualSVM` поддерживает параметр `solver`:

- **`solver="smo"`** — Sequential Minimal Optimization на чистом `numpy`. Стандартный алгоритм для SVM, попарно обновляет $\lambda_i, \lambda_j$ аналитически, без вызова QP-солвера.
- **`solver="scipy"`** — `scipy.optimize.minimize` (метод SLSQP) на той же двойственной задаче:

$$
\min_{\lambda}\ \frac{1}{2}\lambda^{T}H\lambda - \mathbf 1^{T}\lambda
\quad \text{s.t.}\quad
0 \le \lambda_i \le C,\ \sum_i \lambda_i y_i = 0,
$$

где $H_{ij} = y_i y_j K(x_i, x_j)$. Для устойчивости SLSQP к вырожденным (линейным) ядрам в `H` добавляется микро-регуляризация $10^{-8} I$.

Оба варианта прогоняются последовательно на одних и тех же данных; результаты сравниваются между собой и с `sklearn.svm.SVC`.

### 4.2. Алгоритм SMO

**Выбор $i$ (внешний цикл)** — точка с нарушением KKT:

$$
\Bigl(\lambda_i = 0 \ \wedge\ y_i E_i < -\text{tol}\Bigr)
\ \vee\
\Bigl(\lambda_i = C \ \wedge\ y_i E_i > \text{tol}\Bigr)
\ \vee\
\Bigl(0<\lambda_i<C \ \wedge\ |y_i E_i| > \text{tol}\Bigr),
$$

где $E_i = f(x_i) - y_i$.

**Выбор $j$ (внутренний цикл).** Кандидаты упорядочены по $|E_i - E_j|$ по убыванию; берётся первый валидный: $L < H$ и $\eta = 2K_{ij} - K_{ii} - K_{jj} < 0$. Порог проверки $\eta$: `eta >= -1e-12` (защита от деления на ноль).

**Границы:**

$$
\begin{cases}
L = \max(0,\ \lambda_j - \lambda_i), & H = \min(C,\ C + \lambda_j - \lambda_i), \quad y_i \neq y_j,\\[2pt]
L = \max(0,\ \lambda_i + \lambda_j - C), & H = \min(C,\ \lambda_i + \lambda_j), \quad y_i = y_j.
\end{cases}
$$

**Аналитическое обновление:**

$$
\lambda_j^{\text{new}} = \lambda_j - \frac{y_j\,(E_i - E_j)}{\eta}, \qquad
\lambda_j^{\text{new}} \leftarrow \operatorname{clip}\!\bigl(\lambda_j^{\text{new}},\,L,\,H\bigr),
$$

$$
\lambda_i^{\text{new}} = \lambda_i + y_i y_j\bigl(\lambda_j - \lambda_j^{\text{new}}\bigr).
$$

**Пересчёт $b$:**

$$
b = \begin{cases}
b_1 = b - E_i - y_i(\lambda_i^{\text{new}} - \lambda_i)K_{ii} - y_j(\lambda_j^{\text{new}} - \lambda_j)K_{ij}, & 0 < \lambda_i^{\text{new}} < C,\\[2pt]
b_2 = b - E_j - y_i(\lambda_i^{\text{new}} - \lambda_i)K_{ij} - y_j(\lambda_j^{\text{new}} - \lambda_j)K_{jj}, & 0 < \lambda_j^{\text{new}} < C,\\[2pt]
\frac{b_1 + b_2}{2}, & \text{иначе}.
\end{cases}
$$

**Критерий остановки:** `max_passes` подряд-проходов без обновлений **и** максимальное KKT-нарушение $\le \text{tol}$.

### 4.3. Polish-фаза

После основного решателя $b$ может численно отличаться от «свободного» $b$ по свободным SV ($0<\lambda_i<C$). Это даёт остаточное KKT-нарушение порядка $10^{-1}$.

1. Пересчёт:

$$
b_{\text{new}} = \frac{1}{|S_{\text{free}}|}\sum_{i \in S_{\text{free}}}\Bigl(y_i - \sum_{j}\lambda_j y_j K_{ji}\Bigr),
\quad S_{\text{free}} = \{i : 0 < \lambda_i < C\}.
$$

2. Если $|b_{\text{new}} - b| \ge \text{tol}$ — запускается `_smo_lam_only`: SMO с **фиксированным** $b$, обновляется только $\lambda$.
3. Шаги 1–2 повторяются до `n_polish_rounds = 3`, пока $|b_{\text{new}} - b| < \text{tol}$.

После polish `max KKT violation` падает до $\sim 10^{-6}$.

### 4.4. Корректный пересчёт $b$ в конце

Финальный `b` в `fit()` выбирается как лучший из двух кандидатов по KKT:

1. `b_computed` — по `_compute_b`: если есть свободные SV, среднее по ним; иначе — по KKT-границам (для линейного ядра при $C=1.0$ все SV на границе $\lambda=C$, тогда $b = \frac{b_{\text{low}} + b_{\text{high}}}{2}$).
2. `b_solver` — значение, с которым сошёлся сам решатель (SMO/scipy).

Для каждого считается `kkt_of(b)`, и выбирается тот, который даёт меньшее нарушение. Это делает диагностику корректной на вырожденных случаях.

### 4.5. Параметры по умолчанию

```
DualSVM(
    C=1.0, kernel="rbf", gamma="scale",

    tol=1e-5, tol_sv=1e-6,
    max_passes=100, max_iter=5000,
    n_polish_rounds=3,
```

## 7. Отладка: найденные и исправленные проблемы по ходу работы

### 7.1. Недосход SMO из-за «одного кандидата $j$»

**Симптом:** custom SVM делал 7–10 обновлений за проход, accuracy $0.91$ vs $0.97$ у sklearn, SV $20$ vs $89$.

**Причина:** алгоритм брал единственного кандидата $j$ с максимальным $|E_i - E_j|$. Если для этой пары $L \ge H$ или $\eta \ge 0$ — `continue` на внешнем цикле, ложная сходимость.

**Исправление:** перебор **всех** $j$ по убыванию $|E_i - E_j|$ до первой валидной пары.

### 7.2. Грубый `tol` и порог пропуска

**Исправление:** `tol` $10^{-3} \to 10^{-5}$, `tol_sv` $10^{-5} \to 10^{-6}$, порог пропуска $|\Delta\lambda_j| < 10^{-5}$ заменён на $10^{-9}$.

### 7.3. Остаточное KKT-нарушение

**Причина:** в `fit()` после SMO $b$ переопределялось средним по свободным SV, но с этим $b$ SMO не сходилось.

**Исправление:** polish-фаза с фиксированным $b$ и повторной оптимизацией $\lambda$ (п. 5.3).

### 7.4. Вырождение при $\gamma = 1.0$

**Симптом:** accuracy $0.6257$ ниже baseline $0.627$.

**Причина:** RBF-ядро на 30D после стандартизации при $\gamma=1.0$ почти диагонально: $K_{ij} = \exp(-\|x_i - x_j\|^2) \approx \exp(-60) \approx 10^{-26}$. Все точки становятся SV, модель предсказывает majority.

**Исправление:** по умолчанию $\gamma = 0.03 \approx 1/n_{\text{features}}$.

### 8.5. KKT-нарушение для линейного ядра при $C=1.0$

**Симптом:** `[custom scipy] KKT=1.77e+01` при том, что accuracy и SV уже совпадали со sklearn.

1. **Диагностика KKT.** В `fit()` KKT-проверка использовала строгие условия `lam < C`, `lam > 0`. Для линейного ядра все 31 SV стоят на границе $\lambda_i = 1.0 = C$ с точностью $\lambda_i = 0.9999$, и такое $\lambda_i$ ошибочно попадало в «свободные SV», к которым предъявляется требование $|y_i E_i| = 0$. Отсюда KKT $\approx 17$.
2. **Вырожденность прямой задачи.** При $C=1.0$ и линейном ядре свободных SV нет (все $\lambda_i \in \{0, C\}$), поэтому стандартная формула $b = y_i - w^T x_i$ по свободным SV не сработала.

**Исправление:**

- KKT-проверка использует те же пороги `tol_sv`, что и `_compute_b`:
  - $\lambda_i \le \text{tol\_sv}$ → ноль;
  - $\lambda_i \ge C - \text{tol\_sv}$ → граница;
  - иначе — свободный SV.
- `_compute_b` возвращает `b_fallback` (из решателя), если свободных SV нет.
- `fit()` выбирает финальный `b` как **лучший из двух кандидатов** (`b_computed` и `b_solver`) по значению `kkt_of(b)`.

**Результат:** KKT на всех четырёх комбинациях (SMO/scipy × RBF/linear) упал до $10^{-5}$–$10^{-7}$.

## 8. Выводы

1. Двойственная задача SVM решена двумя способами — собственным SMO на `numpy` (для сравнения реализации) и `scipy.optimize.minimize`  Оба дают одинаковый accuracy, совпадающий с `sklearn.svm.SVC`.
2. Kernel trick работает  — классификатор использует только матрицу Грама.
3. Для линейного ядра восстановленный $w$ совпадает с $w$ из `sklearn` с точностью до направления ($\cos = 1.000000$).
4. PCA-2D-визуализация подтверждает нелинейный характер границы для RBF и линейный — для linear.
5. Гиперпараметр $\gamma$ критичен: $\gamma = \texttt{"scale"} \approx 1/n_{\text{features}}$ попадает в оптимум; $\gamma = 1.0$ на 30D вырождает ядро.
