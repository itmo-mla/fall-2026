# Конспект по лабораторной работе 3 (SVM)

## 0. Что вообще делали

Задача - реализовать SVM через решение двойственной задачи по лямбда (а не через прямую задачу с весами w), добавить трюк с ядром для нелинейных границ и сравнить с эталоном sklearn.svm.SVC. Датасет - Banknote Authentication: 1372 банкноты, 4 признака (variance, skewness, curtosis, entropy - статистики вейвлет-преобразования изображения), метка: поддельная (-1) или подлинная (+1).

Весь пайплайн живет в model.py, который дергает data.py, kernels.py, svm_dual.py, cross_val.py и сохраняет графики в plots.

## 2. Двойственная задача по лямбда

Вместо того чтобы искать веса w напрямую, решаем задачу минимизации: минус сумма лямбда_i плюс половина двойной суммы лямбда_i лямбда_j y_i y_j K(x_i,x_j), при ограничениях сумма лямбда_i y_i равна нулю и 0 <= лямбда_i <= C.

В коде (svm_dual.py) это scipy.optimize.minimize методом SLSQP: функция и аналитический градиент считаются векторно через матрицу Грама, равенство - через LinearConstraint, 0<=лямбда<=C - через bounds.

После сходимости (DualSVM.fit): лямбда больше нуля - опорный вектор. Порог w0 усредняется не по всем опорным, а только по опорно-граничным (0 < лямбда < C) - у них отступ гарантированно равен 1, поэтому среднее дает несмещенную оценку. Если таких объектов нет (вырожденный случай), код откатывается на усреднение по всем опорным.

KKT-проверка (критерий, что решатель не сломался, а не просто что метрика хорошая):

- линейное ядро, C=0.046: ограничения на лямбда выполнены, сумма лямбда*y около 1.6e-13 (ноль с точностью до погрешности), доля опорных векторов 0.38 (95 из 250), оптимизатор сошелся, значение функционала -2.843.
- полиномиальное ядро, C=0.1, degree=3: лямбда в допустимых границах, сумма лямбда*y около 1.0e-11, доля опорных 0.10 (25 из 250), сошелся, функционал -0.881.
- RBF-ядро, C=1, gamma=0.25: лямбда в границах, сумма лямбда*y около 9.3e-15, доля опорных 0.20 (50 из 250), сошелся, функционал -24.662.

Все три решения валидны, доля опорных векторов разумная (не 0%, не 100%).

## 3. Трюк с ядром

В двойственной задаче объекты участвуют только через скалярные произведения. Если заменить произведение на функцию K(x_i,x_j), равную скалярному произведению объектов в каком-то (возможно бесконечномерном) преобразованном пространстве, алгоритм начинает строить нелинейную границу, хотя сам остается линейным QP (kernels.py):

- linear - обычное произведение, граница остается прямой;
- polynomial - пространство мономов до степени degree;
- rbf - бесконечномерное пространство, самая гибкая граница.

Гиперпараметры подбирались 5-fold CV на train_sub:

02_cv_linear.png - accuracy выходит на плато 0.992 уже при C=0.046 и дальше не растет. Выбрано минимальное C с максимальным accuracy - не делать регуляризацию слабее, чем нужно.

03_cv_poly.png - degree=3 с C от 0.1 дает CV accuracy 1.0, degree=2 заметно хуже на малом C. coef0 зафиксирован равным 1, чтобы не захламлять сетку и график лишним измерением.

04_cv_rbf.png - лучшая точка C=1, gamma=0.25. Интересно, что 0.25 - это ровно эвристика 1 деленное на число признаков (аналог sklearn scale при стандартизированных признаках), то есть CV независимо подтвердила стандартную эвристику.

## 4. Линейный классификатор (переход двойственная -> прямая)

to_primal_weights считает w как сумму лямбда_i * y_i * x_i по опорным векторам.

Веса после стандартизации признаков (поэтому сравнимы по модулю): variance 1.166, skewness 0.892, curtosis 0.847, entropy -0.093. variance важнее всего, entropy почти не влияет - вес на порядок меньше остальных.

Sanity-check: предсказания через явное w и через сумму лямбда*y*K(x,x_i) с линейным ядром совпали с точностью 1.55e-15, знаки совпали в 100% случаев. Это проверка корректности перехода между постановками задачи, а не метрика качества модели.

## 5. Визуализация

Признаков 4, поэтому границу рисовать негде - вместо этого для каждого ядра отдельно обучается иллюстративная SVM прямо в проекции на 2 главные компоненты (PCA). Это честная граница в том пространстве, где рисуем, но ее метрики несравнимы с настоящими 4-мерными моделями - у нее другое число опорных векторов, чем в KKT-таблице выше, потому что 2D-проекция хуже разделима.

На графиках 05-08 опорные векторы разбиты на два типа: опорно-граничные (0 < лямбда < C, кружок) лежат ровно на краю зазора, опорно-нарушители (лямбда = C, треугольник) - внутри зазора или по чужую сторону.

Для 2D-моделей: линейное ядро - 3 опорно-граничных и 145 опорно-нарушителей (всего 148 из 250); полиномиальное - 8 и 108 (всего 116); RBF - 10 и 115 (всего 125). Во всех трех случаях нарушителей сильно больше - при подобранном по CV C зазор узкий, и почти все опорные объекты оказываются внутри него, а не точно на границе.

08_decision_boundaries_compare.png ставит все три границы рядом на одной сетке: линейная - прямая полоса, poly и RBF подстраиваются под изгиб данных похожим образом, у RBF есть небольшой замкнутый контур вокруг плотной группы поддельных банкнот.

Confusion matrix на test (графики 09-12): линейное ядро - 2 подлинных приняты за поддельные, 10 поддельных за подлинные, accuracy 0.956; poly и RBF (своя реализация) - 0 ошибок, accuracy 1.0; sklearn (лучшее по accuracy ядро - тоже RBF) - тоже 0 ошибок, полностью совпадает со своей реализацией.

## 6. Сравнение с эталоном

Линейное ядро: своя реализация и sklearn дают одинаковые метрики (accuracy 0.956, F1 0.960, 95 опорных векторов), собственная реализация медленнее (0.54 секунды против 0.001).

Полиномиальное ядро: своя реализация дает accuracy 1.0, sklearn с теми же гиперпараметрами - 0.975 (25 опорных векторов против 62). При маленькой подвыборке (250 объектов) и низкой доле опорных (10%) решение двойственной задачи не единственно, SLSQP и libsvm сходятся к разным, но одинаково допустимым с точки зрения KKT точкам - это не ошибка реализации, а свойство задачи с недостаточным количеством данных.

RBF-ядро: своя реализация и sklearn снова совпадают (accuracy 1.0, 50 и 51 опорных векторов соответственно).

sklearn быстрее своей реализации на два-три порядка, потому что использует специализированный решатель libsvm вместо общего scipy.optimize.minimize.

## 7. Оценка качества и ограничения

DummyClassifier (предсказание большинства класса) дает accuracy 0.556, F1 0.715. Линейный SVM - 0.956 и 0.960, poly и RBF - по 1.0. Все модели значимо лучше тривиального baseline.

Главное ограничение всей лабораторной - собственный решатель обучается на подвыборке 250 из 1097, потому что scipy.optimize.minimize на полной матрице Грама (1097 на 1097) работает на порядки медленнее специализированных QP-решателей. sklearn с теми же гиперпараметрами на полном train тоже дает accuracy 1.0, то есть само ограничение - в скорости общего решателя, а не в датасете.

## Вопросы, которые могут задать на защите

Почему не вся выборка? Матрица Грама растет квадратично от числа объектов, время SLSQP - тоже. На 1097 объектах один фит занимал бы минуты, а для CV-сетки по трем ядрам таких фитов нужно больше двухсот.

Почему poly разошелся со sklearn? Неединственность решения QP при малом числе опорных векторов (10%), а не ошибка в реализации - это подтверждено KKT-проверкой (решение валидно) и sanity-check (переход в прямую задачу точен).

Зачем усреднять w0 только по опорно-граничным? Только у них отступ математически точно равен 1 по условиям KKT, у нарушителей отступ меньше 1, усреднение по ним дало бы смещенную оценку порога.

Почему на графиках границ опорных векторов больше, чем в таблице метрик? Это две разные модели: настоящая (4-мерная, используется для метрик) и иллюстративная (2D PCA, только для рисунка) - в 2D классы хуже разделимы, поэтому больше объектов становится опорными.
