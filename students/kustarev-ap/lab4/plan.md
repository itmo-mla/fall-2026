## 2. Реализация PCA через SVD (пункт задания №2)

Теория (лекция): центрируем `X` → `X_c = X - mean(X)` → сингулярное разложение `X_c = U·S·V^T` → главные компоненты — столбцы `V` (направления), собственные значения ковариационной матрицы `λ_k = S_k² / (n-1)`, новые признаки `Z = X_c · V_m` (проекция на первые `m` компонент), приближённое восстановление `X_approx = Z · V_m^T + mean(X)`.

**Вход**: `X_train` (стандартизованный), опционально `X_test` для `transform`.

**Метод** (`pca_svd.py`, класс `PCA_SVD`, без использования `sklearn.decomposition.PCA`):
- `fit(X)`: считает `mean_`, центрирует `X`, вызывает `np.linalg.svd(X_centered, full_matrices=False)`, сохраняет `singular_values_`, `components_` (строки — главные компоненты, как в sklearn-конвенции), `explained_variance_ = S**2 / (n-1)`, `explained_variance_ratio_ = explained_variance_ / explained_variance_.sum()`;
- `transform(X, m)`: `(X - mean_) @ components_[:m].T` → `Z`;
- `inverse_transform(Z, m)`: `Z @ components_[:m] + mean_` → приближение исходных признаков.

**Проверки корректности реализации (sanity-check)**:
- ортонормированность компонент: `‖V_m @ V_m.T - I‖ < 1e-8`;
- при `m = d` (все 8 компонент) восстановление точное: `‖X_approx - X‖ < 1e-8`;
- `explained_variance_ratio_.sum() == 1` (при полном `m=d`).

**Выход**: объект `PCA_SVD` с атрибутами `components_`, `singular_values_`, `explained_variance_ratio_`; функции `transform`/`inverse_transform` для произвольного `m`. Эти проверки идут в таблицу "sanity-check" раздела 5.

## 3. Эффективная размерность выборки (пункт задания №3)

**Вход**: обученный `PCA_SVD` на `X_train` (все 8 компонент), `X_test` для проверки обобщения.

**Метод** (`dimensionality.py`):
- scree-график: собственные значения `λ_k` по убыванию — ищем "излом" (elbow);
- накопленная доля дисперсии `cumsum(explained_variance_ratio_)` — порог 90% и 95% (две горизонтальные линии), выбираем минимальное `m`, при котором накопленная доля ≥ 95%;
- ошибка восстановления `MSE(m) = mean(‖X - X_approx(m)‖²)` по train и по test — должна монотонно убывать с `m`, достигая 0 при `m=d`; теоретически `MSE(m) = mean(λ_{m+1..d})` — проверяем совпадение аналитической и эмпирической ошибки (ещё один sanity-check);
- итоговая эффективная размерность `m*` — минимум между критерием дисперсии (95%) и визуальным изломом scree-графика; если расходятся — обсуждается в отчёте, какой критерий информативнее.

**Выход**: `03_scree_cumvar.png`, `04_reconstruction_error.png`, таблица "размерность vs качество", значение `m*`.

**Графики:**

- `03_scree_cumvar.png` — комбинированный график: столбцы (`bar`, цвет `#4472C4`) — собственные значения `λ_k` по индексу компоненты (левая ось Y, «собственное значение»); линия (цвет `#ED7D31`, с маркерами) — накопленная доля объяснённой дисперсии (правая ось Y, 0-100%). Две горизонтальные пунктирные серые линии на уровнях 90% и 95%. Вертикальная пунктирная линия на выбранном `m*` с аннотацией. Заголовок: «Scree-график и накопленная доля дисперсии».
- `04_reconstruction_error.png` — линейный график: ось X — число компонент `m` (1..8), ось Y — MSE восстановления (возможно, логарифмическая шкала). Две линии: train (`#4472C4`, сплошная) и test (`#ED7D31`, пунктирная) — должны быть близки, если `m*` не переобучен под train. Вертикальная пунктирная линия на `m*`. Заголовок: «Ошибка восстановления от числа компонент».

**Таблица «размерность vs качество»** (`dimensionality.py`, печатается в отчёт): столбцы `m`, `cum_variance_ratio`, `MSE_train`, `MSE_test`, строка с выбранным `m*` выделяется отдельно/жирным в тексте README.

**Бонус (не обязательный пункт задания, но полезен для защиты, вопрос 13)**: линейная регрессия `y ~ Z_m` для `m ∈ {2, m*, 8}` (через `np.linalg.lstsq`, не `sklearn.linear_model`, т.к. это не эталон, а демонстрация) — сравнение `R²` на test с регрессией на полных признаках `y ~ X`, чтобы показать, что сохранённая доля дисперсии признаков не гарантирует сохранение полезной информации о таргете. Оформляется отдельной небольшой таблицей `m`, `R²_test`, без графика.

## 4. Эквивалентность с эталонной реализацией (пункт задания №4)

**Вход**: тот же `X_train`/`X_test`, обученный `PCA_SVD` и `sklearn.decomposition.PCA(n_components=8)` (эталон, разрешено правилом 7).

**Метод** (`compare_sklearn.py`):
- обучить `sklearn.decomposition.PCA` на тех же стандартизованных `X_train`;
- сравнить `explained_variance_ratio_` почленно (должны совпадать с точностью до `1e-10`);
- сравнить компоненты `components_` — знаки собственных векторов могут отличаться (теоретический вопрос 14, неустойчивость знака в SVD/eig), поэтому сравнение через `|cos similarity|` между соответствующими строками `V_mine` и `V_sklearn` (должно быть ≈1), а не через прямое поэлементное равенство;
- выровнять знаки (`sign_k = sign(cos_similarity_k)`) и после выравнивания сравнить проекции `Z_mine` и `Z_sklearn` — максимальное абсолютное отклонение должно быть близко к 0;
- сравнить восстановленные данные `X_approx` при одинаковом `m` — должны совпадать.

**Выход**: таблица эквивалентности, графики `06_compare_explained_variance.png`, `07_compare_pc_scatter.png`.

**Графики:**

- `06_compare_explained_variance.png` — сгруппированная столбчатая диаграмма (grouped bar chart): ось X — индекс компоненты (1-8), ось Y — доля объяснённой дисперсии; два столбца на каждый индекс — своя реализация (`#4472C4`) и sklearn (`#ED7D31`). Заголовок: «Доля объяснённой дисперсии: своя реализация vs sklearn». Легенда: «своя реализация», «sklearn».
- `07_compare_pc_scatter.png` — две панели (`1×2 subplot`, общий масштаб осей): слева — проекция train на первые 2 компоненты своей реализации, справа — то же для sklearn (после выравнивания знака). Точки раскрашены по таргету `strength` палитрой `viridis`, общий colorbar для обеих панелей. Заголовок общий: «Проекция на первые 2 компоненты: своя реализация vs sklearn» — визуально панели должны быть зеркально идентичны.

**Таблица эквивалентности**: столбцы `компонента`, `|cos similarity|`, `Δ(explained_variance_ratio)`, `max|Z_mine_aligned - Z_sklearn|`, `max|X_approx_mine - X_approx_sklearn|` (при `m=8`). Все значения — близкие к 0 / к 1, что подтверждает корректность собственной реализации.

## 5. Сквозная оценка качества (не отдельный пункт задания, но обязательна по итогу)

- Единый train/test split с фиксированным `random_state`, стандартизация обучена только на train.
- Санити-чеки реализации PCA: ортонормированность компонент, точное восстановление при `m=d`, совпадение аналитической (`Σλ_{m+1..d}`) и эмпирической ошибки восстановления.
- Эффективная размерность проверяется не только по train (накопленная дисперсия), но и по test (ошибка восстановления) — чтобы показать, что выбор `m*` не является переобучением.
- Эквивалентность с эталоном — через инвариантные к знаку метрики (`cos similarity`, разница после выравнивания знака), а не через наивное поэлементное сравнение векторов.
- Бонусная регрессия на главных компонентах — иллюстрация того, что PCA — обучение без учителя и не гарантирует сохранение полезной информации о `y` (вопрос 8, 13).

**Таблицы вместо текста**:
- таблица sanity-check PCA: `‖V@V.T - I‖`, `‖X_approx(m=d) - X‖`, `Σ explained_variance_ratio_`;
- таблица «размерность vs качество» (раздел 3);
- таблица эквивалентности со sklearn (раздел 4);
- (бонус) таблица `R²` регрессии на `m` компонентах.
