## 1. Постановка задачи и обозначения

Как на слайде 3:

- $X$ — множество объектов (пассажиров), $Y$ — множество ответов. У нас бинарная классификация, $Y = \lbrace 0, 1 \rbrace$: 0 — погиб, 1 — выжил.
- $X^\ell = (x_i, y_i)_{i=1}^{\ell}$ — обучающая выборка, $\ell = 712$.
- Объект $x = (x^1, \dots, x^n)$ — вектор из $n = 8$ числовых признаков.
- Алгоритм $a: X \to Y$ — правило, которое по признакам объекта выдаёт класс.

**Гипотеза компактности** (слайд 3): близкие объекты, как правило, лежат в одном классе. На ней построены все метрические методы: класс нового объекта определяется по классам ближайших к нему обучающих объектов. Для Titanic гипотеза выполняется лишь частично: похожие пассажиры (одного пола, класса и возраста) часто разделили одну судьбу, но далеко не всегда. Количественно это видно по профилю компактности (раздел 8): даже ближайший сосед в 25% случаев принадлежит другому классу. Поэтому ошибка никогда не опускается до нуля: минимальный LOO-риск равен 0.178.

## 2. Подготовка данных

Код: `source/data_preparation.py`.

### 2.1. Стратифицированное разбиение

Исходные 891 строка делятся на train (80%) и test (20%) функцией `train_test_split(..., stratify=Survived)`. **Стратификация** означает, что доля каждого класса в train и test такая же, как во всём датасете. Разбиение делается отдельно внутри каждого класса:

| Класс | Всего | Train | Test |
|---|---|---|---|
| Погиб | 549 | 439 | 110 |
| Выжил | 342 | 273 | 69 |

Без стратификации случайное разбиение могло бы, например, дать в test 30% выживших вместо 38%, и оценки качества на train и test были бы несопоставимы.

**Тестовая выборка в обучении не участвует вообще.** Все статистики (медиана, мода, среднее, дисперсия) считаются только по train. Иначе информация из test «протекла» бы в модель (утечка данных, data leakage), и оценка качества на test стала бы завышенной.

### 2.2. Кодирование признаков

| Признак | Преобразование | Почему |
|---|---|---|
| `Pclass` | как есть: 1, 2, 3 | порядковый признак: 1-й класс «ближе» ко 2-му, чем к 3-му, поэтому числовое расстояние осмысленно |
| `Sex` | female → 1, male → 0 | бинарный признак |
| `Age` | пропуски → медиана train (28.5 лет) | медиана устойчива к выбросам, в отличие от среднего |
| `SibSp`, `Parch` | как есть | количества |
| `Fare` | $\ln(1 + \text{Fare})$ | см. ниже |
| `Embarked` | one-hot: `Embarked_C`, `Embarked_Q` | см. ниже |

**Почему логарифм цены.** Распределение `Fare` сильно скошено вправо: половина билетов дешевле 15 фунтов, а самые дорогие стоят 512. Без логарифма после стандартизации пассажир с билетом за 512 оказался бы на 10 стандартных отклонений от среднего, и в расстоянии до него доминировал бы этот один признак. Логарифм сжимает большие значения. $+1$ нужен потому, что у 15 пассажиров цена билета 0, а $\ln 0$ не определён, тогда как $\ln(1 + 0) = 0$.

**Почему one-hot для порта.** Порт посадки — номинальный признак: у портов C, Q, S нет порядка. Если закодировать их как 0, 1, 2, получится, что Шербур «ближе» к Квинстауну, чем к Саутгемптону, а это бессмысленно. One-hot заводит бинарный признак для каждого значения. Третий столбец (`Embarked_S`) не нужен: он однозначно определяется двумя другими (S ⇔ C = 0 и Q = 0).

### 2.3. Стандартизация

$$\tilde{x}^j = \frac{x^j - \mu_j}{\sigma_j}, \qquad \mu_j = \frac{1}{\ell} \sum_{i=1}^{\ell} x_i^j, \qquad \sigma_j = \sqrt{\frac{1}{\ell} \sum_{i=1}^{\ell} \left(x_i^j - \mu_j\right)^2}.$$

После стандартизации каждый признак на train имеет среднее 0 и дисперсию 1. Зачем это нужно, показано в следующем разделе.

## 3. Расстояние между объектами

Код: `pairwise_distances` в `source/knn.py`.

Используется евклидова метрика (слайд 5):

$$\rho(x, x_i) = \left( \sum_{j=1}^{n} \left| x^j - x_i^j \right|^2 \right)^{1/2}.$$

**Связь стандартизации с весами признаков.** На слайде 5 приведена обобщённая метрика Минковского с весами $w_j$. Её первая роль — «нормировка, приведение к общему масштабу». Подставим стандартизованные признаки в евклидову метрику:

$$\rho(\tilde{x}, \tilde{x}_i)^2 = \sum_{j=1}^{n} \left( \frac{x^j - \mu_j}{\sigma_j} - \frac{x_i^j - \mu_j}{\sigma_j} \right)^2 = \sum_{j=1}^{n} \frac{1}{\sigma_j^2} \left| x^j - x_i^j \right|^2.$$

Сдвиг $\mu_j$ сокращается, и получается метрика Минковского с $p = 2$ и весами $w_j = 1/\sigma_j^2$. Значит, стандартизация — частный случай взвешенной метрики, где вес признака обратно пропорционален его разбросу. Без неё возраст (разброс около 13 лет) полностью подавил бы пол (разброс около 0.5), хотя пол — самый информативный признак для выживания.

**Как это считается в коде.** Матрица всех попарных расстояний строится за одну векторную операцию: `A[:, None, :] - B[None, :, :]` даёт массив разностей размера $m \times \ell \times n$, после чего берётся норма по последней оси.

## 4. Обобщённый метрический классификатор

Слайд 7. Для объекта $x$ все обучающие объекты сортируются по расстоянию:

$$\rho\left(x, x^{(1)}\right) \le \rho\left(x, x^{(2)}\right) \le \dots \le \rho\left(x, x^{(\ell)}\right),$$

где $x^{(i)}$ — $i$-й сосед объекта $x$, а $y^{(i)}$ — его класс. Каждый класс набирает «голоса» соседей:

$$\Gamma_y(x) = \sum_{i=1}^{\ell} \left[ y^{(i)} = y \right] w(i, x), \qquad a(x) = \arg\max_{y \in Y} \Gamma_y(x).$$

- $[\,\cdot\,]$ — **нотация Айверсона**: 1, если условие в скобках истинно, иначе 0.
- $w(i, x)$ — **вес** $i$-го соседа, неотрицательный и не возрастающий по $i$: чем дальше сосед, тем меньше его голос.
- $\Gamma_y(x)$ — **оценка близости** объекта $x$ к классу $y$.

Все методы лекции различаются только выбором $w(i, x)$ (слайды 8–11):

| Метод | $w(i, x)$ | Где в лабораторной |
|---|---|---|
| 1NN | $[i \le 1]$ | `NearestNeighbor` в `run_lab.py`, отбор эталонов |
| kNN | $[i \le k]$ | — |
| взвешенный kNN | $[i \le k] \, w_i$ | sklearn с весами $1/\rho$ |
| окно Парзена фиксированной ширины | $K\left(\rho(x, x^{(i)}) / h\right)$ | — |
| окно Парзена переменной ширины | $K\left(\rho(x, x^{(i)}) / \rho(x, x^{(k+1)})\right)$ | `ParzenKNN` — основной метод |

**Случай двух классов** (слайд 12). При $Y = \lbrace 0, 1 \rbrace$:

$$a(x) = \left[ \Gamma_1(x) > \Gamma_0(x) \right],$$

то есть объект относится к классу «Выжил», если выжившие соседи в сумме «весят» больше погибших. На слайде то же самое записано через знак: $\text{sign}(\Gamma_{+1} - \Gamma_{-1})$ для $Y = \lbrace -1, +1 \rbrace$.

## 5. Метод окна Парзена переменной ширины

Код: `gaussian_kernel`, `parzen_weights`, `ParzenKNN` в `source/knn.py`.

### 5.1. Формула

Реализована формула со слайда 11 с гауссовым ядром со слайда 34:

$$a(x; X^\ell, k, K) = \arg\max_{y \in Y} \sum_{i=1}^{\ell} [y_i = y] \, K\left( \frac{\rho(x, x_i)}{\rho\left(x, x^{(k+1)}\right)} \right), \qquad K(r) = G(r) = e^{-2r^2}.$$

Разберём составляющие:

- **Ядро** $K(r)$ переводит «нормированное расстояние» $r$ в вес. По слайду 11 оно не возрастает и положительно на $[0, 1]$. Гауссово ядро $G(r) = e^{-2r^2}$ из лекции этим условиям удовлетворяет.
- **Ширина окна** $h$ задаёт масштаб расстояний: объекты на расстоянии много меньше $h$ получают вес около $K(0) = 1$, объекты на расстоянии порядка $h$ — заметно меньший.
- **Переменная ширина** $h(x) = \rho(x, x^{(k+1)})$ зависит от точки $x$ и равна расстоянию до её $(k+1)$-го соседа. В густонаселённых областях (например, мужчины 3-го класса — их очень много) окно узкое, в разреженных (например, пожилые пассажиры 1-го класса) — широкое. Поэтому в окно всегда попадает примерно одинаковое число объектов. При фиксированном $h$ в разреженной области окно могло бы оказаться пустым, и классифицировать было бы не по чему (слайд 36).
- Суммирование идёт по **всем** $\ell$ обучающим объектам. Порядок слагаемых не важен, поэтому объекты можно не ранжировать (как на слайде 18).

Параметр у метода один — $k$. Он задаёт ширину окна, а значит, и число объектов, которые реально влияют на решение.

### 5.2. Почему $(k+1)$-й сосед

В лекции подразумеваются в первую очередь ядра с конечным носителем, например ядро Епанечникова $E(r) = (1 - r^2)[|r| \le 1]$ (слайд 34). Для такого ядра при $h(x) = \rho(x, x^{(k+1)})$:

- $k$ ближайших соседей имеют $r < 1$ и получают **положительные** веса;
- $(k+1)$-й сосед имеет $r = 1$ и вес $K(1) = 0$;
- все остальные имеют $r > 1$ и вес 0.

Голосуют ровно $k$ соседей. Если бы ширина окна равнялась $\rho(x, x^{(k)})$, $k$-й сосед получал бы вес $K(1) = 0$, и голосовали бы только $k - 1$. Поэтому в знаменателе стоит $(k+1)$-й сосед.

### 5.3. Веса при гауссовом ядре (вывод)

У гауссова ядра носитель бесконечный: $G(r) > 0$ при любом $r$, так что формально голосуют все $\ell$ объектов. Посмотрим, какие у них веса.

**$k$ ближайших соседей.** Для $i \le k$: $\rho(x, x^{(i)}) \le \rho(x, x^{(k+1)}) = h(x)$, поэтому

$$r_i = \frac{\rho\left(x, x^{(i)}\right)}{h(x)} \in [0, 1] \quad \Rightarrow \quad w_i = e^{-2r_i^2} \in \left[ e^{-2}, 1 \right] \approx [0.14, 1].$$

Ближний сосед весит до 7 раз больше дальнего, то есть расстояние внутри окна учитывается существенно.

**Объекты вне окна.** $(k+1)$-й сосед получает вес $e^{-2} \approx 0.135$, объект на расстоянии $2h$ — $e^{-8} \approx 3.4 \cdot 10^{-4}$, на расстоянии $3h$ — $e^{-18} \approx 1.5 \cdot 10^{-8}$. Вклад далёких объектов быстро убывает, и решение определяется окрестностью примерно из $k$ соседей. На практике вес далёких объектов важен только тогда, когда голоса внутри окна почти поровну.

### 5.4. Вырожденный случай $h(x) = 0$

Если $(k+1)$-й сосед совпадает с $x$ (в Titanic есть пассажиры с одинаковыми признаками), то $h(x) = 0$, и делить на $h$ нельзя. В этом случае голосуют только точные совпадения: $w_i = [\rho(x, x_i) = 0]$. Это предел формулы при $h \to 0$: вес любого объекта на ненулевом расстоянии стремится к $e^{-\infty} = 0$.

### 5.5. Как это считается в коде

1. Матрица расстояний от $m$ объектов-запросов до $\ell$ обучающих: $D_{ij} = \rho(x_i, x_j)$.
2. `np.partition(D, k, axis=1)[:, k]` — $(k+1)$-е по величине расстояние в каждой строке, то есть $h(x)$. `partition` находит $(k+1)$-й элемент за $O(\ell)$ без полной сортировки. При нумерации с нуля это элемент с индексом $k$.
3. `parzen_weights` — матрица весов $W_{ij} = G(D_{ij} / h(x_i))$ размера $m \times \ell$.
4. Суммы по классам: $\Gamma = W \cdot E$, где $E$ — матрица $\ell \times |Y|$ с $E_{jy} = [y_j = y]$ (one-hot кодирование ответов). Одно матричное умножение даёт все $\Gamma_y(x_i)$.
5. `argmax` по классам — предсказание.

**Обучение** (`fit`) сводится к запоминанию выборки — *lazy learning* (слайд 8). Вся работа происходит при предсказании.

## 6. Подбор k по LOO

Код: `loo_risk_curve` в `source/knn.py`, график `graphs/loo_empirical_risk.png`.

### 6.1. Определение

**Скользящий контроль с исключением по одному** (leave-one-out, LOO), слайд 8: каждый объект по очереди исключается из выборки и классифицируется по остальным. Считается доля ошибок:

$$\text{LOO}(k) = \frac{1}{\ell} \sum_{i=1}^{\ell} \Big[ a\left(x_i;\ X^\ell \setminus \lbrace x_i \rbrace,\ k\right) \ne y_i \Big], \qquad k^* = \arg\min_{k \in \lbrace 1, \dots, 50 \rbrace} \text{LOO}(k).$$

На слайде это сумма без множителя $1/\ell$, то есть число ошибок. У нас — доля ошибок (**эмпирический риск**). На $\arg\min$ это не влияет: деление на константу $\ell$ не меняет, где достигается минимум. При равенстве рисков выбирается меньшее $k$.

### 6.2. Почему объект нужно исключать

Если классифицировать $x_i$ по всей выборке, включая его самого, то $x_i$ окажется своим же ближайшим соседом на расстоянии 0, получит вес $G(0) = 1$ и «проголосует» за правильный ответ. Слайд 9 показывает, к чему это приводит: такая **смещённая** оценка (синяя кривая) при малом числе соседей даёт почти нулевую ошибку, хотя честная LOO-ошибка (красная) там максимальна. В коде на диагонали матрицы расстояний стоит $+\infty$ (`np.fill_diagonal(distances, np.inf)`). Тогда вес объекта для самого себя равен $G(\infty) = 0$, и он не может стать $(k+1)$-м соседом.

### 6.3. Эффективное вычисление

Наивный LOO «обучает» модель $\ell$ раз для каждого из 50 значений $k$. Для метрических методов это не нужно:

1. Матрица расстояний $\ell \times \ell$ считается **один раз**. Исключить $x_i$ из выборки — то же самое, что считать его расстояние до самого себя равным $+\infty$.
2. Для каждого $k$ `np.partition` находит ширину окна во всех строках, после чего считаются матрица весов и одно матричное умножение на one-hot матрицу ответов.

Итого $O(\ell^2 n + k_{\max} \ell^2)$ операций вместо $O(k_{\max} \cdot \ell \cdot \ell^2 n)$ при наивном подходе.

### 6.4. Результат и интерпретация

Минимум $\text{LOO}(6) = 0.178$: 127 ошибок из 712. Форма кривой отражает компромисс между смещением и разбросом:

- **Малые $k$** (при $k = 1$ риск 0.223): окно узкое, решение зависит от одного-двух ближайших соседей. Если сосед — шумовой объект (например, мужчина 3-го класса, который выжил), вероятна ошибка. Модель **переобучается**: разделяющая поверхность очень изрезана. Это аналог узкого окна $h = 0.05$ на слайде 12.
- **Большие $k$** (при $k \approx 50$ риск около 0.22): окно захватывает далёкие объекты из других областей, локальная структура сглаживается, и начинает преобладать больший класс «Погиб». Модель **недообучается** — аналог $h = 5$ на слайде 17.
- **Середина** ($k = 4$–$11$, риск 0.178–0.183): кривая пологая, значит выбор устойчив, и небольшое изменение $k$ почти не меняет качество.
- **Скачок при $k = 16$** (до 0.199): окно становится настолько широким, что начинает захватывать соседние группы пассажиров с другой судьбой.

Вид кривой согласуется со слайдом 9 для Iris: быстрое падение, плато, рост.

**Замечание.** $\text{LOO}(1) = 0.223$ для окна Парзена — не то же самое, что LOO для 1NN (0.246, раздел 8). При $k = 1$ окно равно расстоянию до 2-го соседа: первый сосед получает вес из $[e^{-2}, 1]$, второй — $e^{-2}$, остальные — меньше. Решение принимается не по одному соседу, поэтому ошибка ниже.

## 7. Сравнение со sklearn

Код: `run_lab.py`.

Сравниваются две версии `KNeighborsClassifier` с тем же $k = 6$.

**1. sklearn с весами окна Парзена.** `n_neighbors` равно размеру обучающей выборки (712), то есть «соседями» считаются все объекты, как в формуле со слайда 11. В параметр `weights` передана та же функция `parzen_weights`. sklearn передаёт ей массив расстояний до всех объектов, отсортированный по возрастанию. Функция берёт из него $(k+1)$-е расстояние как ширину окна и возвращает веса $G(\rho / h)$. Затем sklearn суммирует веса по классам и берёт `argmax` — ровно как наш код. Поэтому при правильной реализации предсказания должны совпасть. Они совпадают на 100% тестовых объектов — это проверка корректности нашей реализации.

**2. sklearn KNN с весами $1/\rho$** (`weights="distance"`) — стандартный взвешенный kNN: голосуют $k$ ближайших соседей с весом $w(i, x) = [i \le k] / \rho(x, x^{(i)})$. Результат: accuracy 0.821 против 0.832 у окна Парзена.

**Значима ли разница?** Оценим стандартную ошибку accuracy на тесте. Считаем, что каждый из $m = 179$ тестовых объектов классифицируется верно независимо с вероятностью $p \approx 0.83$. Тогда число верных ответов распределено биномиально, и

$$\text{SE} = \sqrt{\frac{p(1 - p)}{m}} = \sqrt{\frac{0.83 \cdot 0.17}{179}} \approx 0.028.$$

Разница $0.832 - 0.821 = 0.011$ (2 объекта) меньше половины стандартной ошибки, то есть статистически незначима. Это согласуется с выводом лекции (слайды 38–39): **качество слабо зависит от вида ядра** и сильно — от ширины окна и метрики.

## 8. Полный скользящий контроль и профиль компактности

Код: `ccv_weights`, `compactness_profile`, `ccv` в `source/reference_selection.py`, график `graphs/compactness_profile.png`.

Этот раздел — теоретическая основа отбора эталонов (слайды 20–25).

### 8.1. Полный скользящий контроль (CCV)

Пусть $X^L$ — выборка из $L$ объектов. Разобьём её на обучающую часть $X^\ell$ и контрольную $X^q$, $L = \ell + q$. **Полный скользящий контроль** (complete cross-validation, CCV) — доля ошибок на контроле, усреднённая по **всем** $C_L^\ell$ таким разбиениям (слайд 20):

$$\mathrm{CCV}(X^L) = \frac{1}{C_L^\ell} \sum_{X^L = X^\ell \sqcup X^q} \frac{1}{q} \sum_{x_i \in X^q} \Big[ a(x_i; X^\ell) \ne y_i \Big].$$

На слайдах длина контроля обозначена $k$. Здесь она обозначена $q$, чтобы не путать с числом соседей. $C_n^j = \dfrac{n!}{j!\,(n-j)!}$ — число сочетаний, $\sqcup$ — разбиение на непересекающиеся части.

CCV — «идеальная» оценка обобщающей способности: она не зависит от случайного выбора разбиения. Напрямую её не посчитать: при $L = 712$, $q = 142$ число разбиений $C_{712}^{570}$ имеет порядка 150 цифр. Но для 1NN CCV выражается аналитически.

**При $q = 1$** контроль состоит из одного объекта, разбиений $L$ штук, и CCV совпадает с LOO (слайд 20).

### 8.2. Профиль компактности

**Профиль компактности** (слайд 21) — доля объектов, у которых $m$-й сосед лежит в другом классе:

$$\Pi(m) = \frac{1}{L} \sum_{i=1}^{L} \left[ y_i \ne y_i^{(m)} \right], \qquad m = 1, \dots, L - 1,$$

где $x_i^{(m)}$ — $m$-й сосед объекта $x_i$ среди остальных объектов выборки, $y_i^{(m)}$ — его класс.

- $\Pi(1)$ — это в точности LOO для 1NN: объект классифицируется по ближайшему соседу, и ошибка возникает, когда тот из другого класса.
- Если гипотеза компактности выполняется, $\Pi(m)$ мал при малых $m$ (ближайшие соседи из своего класса) и растёт с ростом $m$ (слайд 22, первые столбцы).
- Если классы перемешаны, $\Pi(m)$ почти постоянен (слайд 22, последний столбец).

**На Titanic** (левый график `compactness_profile.png`, серая линия) профиль почти горизонтальный: $\Pi(m) \approx 0.25$ при всех $m$ от 1 до 17, $\Pi(1) = 0.246$. Ближайший сосед «врёт» так же часто, как 15-й. Это похоже на третий столбец слайда 22: сложная граница с сильным перекрытием классов.

### 8.3. Теорема: CCV для 1NN через профиль компактности (вывод)

**Утверждение** (слайды 23, 25):

$$\mathrm{CCV}(X^L) = \sum_{m=1}^{q} \Pi(m) \, R(m), \qquad R(m) = \frac{C_{L-1-m}^{\ell-1}}{C_{L-1}^{\ell}}.$$

**Вывод.** Зафиксируем объект $x_i$ и его соседей $x_i^{(1)}, x_i^{(2)}, \dots$ в порядке возрастания расстояния.

1. $x_i$ даёт вклад в CCV только тогда, когда он в контроле. Там его классифицирует ближайший к нему объект **из обучения**.
2. Ближайшим обучающим объектом будет $m$-й сосед $x_i^{(m)}$ тогда и только тогда, когда первые $m - 1$ соседей попали в контроль, а $m$-й — в обучение.
3. Посчитаем число разбиений, где $x_i \in X^q$, $x_i^{(1)}, \dots, x_i^{(m-1)} \in X^q$, $x_i^{(m)} \in X^\ell$. Положение $m + 1$ объекта зафиксировано: $m$ из них в контроле, 1 в обучении. Остальные $L - m - 1$ объектов распределяются свободно, но в обучение должно попасть ещё $\ell - 1$ из них. Число способов: $C_{L-1-m}^{\ell-1}$.
4. Контроль вмещает $q$ объектов, а в нём уже $x_i$ и $m - 1$ соседей, поэтому $m \le q$.
5. Ошибка при этом возникает, если $y_i \ne y_i^{(m)}$. Собираем:

$$\mathrm{CCV} = \frac{1}{q \, C_L^\ell} \sum_{i=1}^{L} \sum_{m=1}^{q} \left[ y_i \ne y_i^{(m)} \right] C_{L-1-m}^{\ell-1}.$$

6. Упростим знаменатель:

$$\frac{C_L^\ell}{C_{L-1}^\ell} = \frac{L! \,/\, (\ell! \, q!)}{(L-1)! \,/\, (\ell! \, (q-1)!)} = \frac{L}{q} \quad \Rightarrow \quad q \, C_L^\ell = L \, C_{L-1}^\ell.$$

7. Подставляем и меняем порядок суммирования:

$$\mathrm{CCV} = \sum_{m=1}^{q} \underbrace{\frac{1}{L} \sum_{i=1}^{L} \left[ y_i \ne y_i^{(m)} \right]}_{\Pi(m)} \cdot \underbrace{\frac{C_{L-1-m}^{\ell-1}}{C_{L-1}^{\ell}}}_{R(m)}. \qquad \blacksquare$$

**Замечание к слайдам.** На слайдах 21 и 24 множитель записан как $C_{L-1}^{\ell-1-m} / C_L^\ell$, а на слайдах 23 и 25 — как $C_{L-1-m}^{\ell-1} / C_{L-1}^{\ell}$. Вывод выше даёт второй вариант, он и реализован в коде.

### 8.4. Свойства весов $R(m)$ (вывод)

**Смысл.** $R(m)$ — вероятность того, что при случайном разбиении ближайшим обучающим соседом контрольного объекта окажется именно его $m$-й сосед. Тогда CCV — это ожидаемая доля ошибок.

**Сумма равна 1.** По тождеству «хоккейной клюшки» $\sum_{j=r}^{n} C_j^r = C_{n+1}^{r+1}$:

$$\sum_{m=1}^{q} C_{L-1-m}^{\ell-1} = \sum_{j=\ell-1}^{L-2} C_j^{\ell-1} = C_{L-1}^{\ell} \quad \Rightarrow \quad \sum_{m=1}^{q} R(m) = 1.$$

Значит, CCV — **средневзвешенное** значение профиля компактности. Если все соседи всех объектов из чужого класса ($\Pi \equiv 1$), то $\mathrm{CCV} = 1$.

**Первый вес:**

$$R(1) = \frac{C_{L-2}^{\ell-1}}{C_{L-1}^{\ell}} = \frac{(L-2)! \,/\, ((\ell-1)! \, (q-1)!)}{(L-1)! \,/\, (\ell! \, (q-1)!)} = \frac{\ell}{L-1}.$$

Это вероятность того, что конкретный сосед попал в обучение.

**Отношение соседних весов** (слайд 24):

$$\frac{R(m+1)}{R(m)} = \frac{C_{L-2-m}^{\ell-1}}{C_{L-1-m}^{\ell-1}} = \frac{L - 1 - m - (\ell - 1)}{L - 1 - m} = \frac{q - m}{L - 1 - m} < \frac{q}{L - 1}.$$

Последнее неравенство верно, потому что $q < L - 1$. Веса убывают **быстрее геометрической прогрессии** со знаменателем $q / (L-1)$.

**При $q = 1$:** $R(1) = \ell / (L - 1) = 1$, и $\mathrm{CCV} = \Pi(1) = \mathrm{LOO}$ для 1NN, как и должно быть.

**Наши числа.** $L = 712$, длина контроля $q = 142$ (20%, как при разбиении train/test), $\ell = 570$:

- $R(1) = 570/711 \approx 0.802$, $R(2) \approx 0.159$, $R(3) \approx 0.031$;
- знаменатель прогрессии $q/(L-1) = 142/711 \approx 0.2$;
- слагаемые с $R(m) < 10^{-12}$ отбрасываются, остаётся $m \le 17$ (правый график `compactness_profile.png`, логарифмическая шкала). Отброшенный хвост в сумме меньше $10^{-12}$.

Вывод слайда 24 — «CCV слабо зависит от длины контроля»: какую бы долю контроля мы ни выбрали, CCV определяется в основном $\Pi(1)$ и $\Pi(2)$. Для всей обучающей выборки $\mathrm{CCV} = 0.250$, что почти равно $\Pi(1) = 0.246$.

### 8.5. Профиль компактности относительно эталонов

Пусть классификатор 1NN ищет соседей не среди всей выборки, а только среди подмножества **эталонов** $\Omega \subseteq X^L$ (слайд 25). Тогда в формулу входит $m$-й сосед из $\Omega$:

$$\Pi(m, \Omega) = \frac{1}{L} \sum_{i=1}^{L} \left[ y_i \ne y_i^{(m \mid \Omega)} \right], \qquad \mathrm{CCV}(\Omega) = \frac{1}{L} \sum_{i=1}^{L} \underbrace{\sum_{m=1}^{q} \left[ y_i \ne y_i^{(m \mid \Omega)} \right] R(m)}_{T(x_i, \Omega)}.$$

- Сумма берётся по **всем** $L$ объектам: эталоны должны правильно классифицировать всю выборку.
- $x_i^{(m \mid \Omega)}$ — $m$-й ближайший к $x_i$ эталон. Сам $x_i$ не может быть своим соседом, даже если он эталон.
- $T(x_i, \Omega)$ — **вклад** объекта $x_i$ в CCV.
- Если эталонов меньше $m$, соответствующее слагаемое равно 0.

В коде (`_neighbor_errors`) для каждого объекта строятся отсортированные расстояния до первых 17 эталонов и индикаторы $[y_i \ne y_i^{(m \mid \Omega)}]$. После этого $T(x_i, \Omega)$ — скалярное произведение индикаторов на вектор $R$.

## 9. Отбор эталонов: жадное добавление по CCV

Код: `greedy_add_references` в `source/reference_selection.py`, графики `graphs/selection_history.png`, `graphs/selected_references.png`.

### 9.1. Задача отбора эталонов

Слайд 25: требуется найти подмножество **эталонов** $\Omega \subseteq X^L$, на котором классификатор 1NN $a(x; \Omega)$ работает как можно лучше. Критерий качества — $\mathrm{CCV}(\Omega) \to \min$. Зачем это нужно:

1. **Скорость и память.** Классификация нового объекта требует расстояний до всех объектов базы, $O(|\Omega| \cdot n)$. Если база в 9 раз меньше, поиск соседей в 9 раз быстрее.
2. **Устранение шума.** 1NN запоминает каждый объект выборки, в том числе выбросы. Из-за одного выжившего мужчины 3-го класса 1NN ошибается на всех похожих на него погибших. Если такие объекты не включать в эталоны, классификация их окрестности исправляется.

Объекты выборки делятся на три типа (слайд 28):

- **эталонные** — входят в $\Omega$ и определяют классификацию;
- **шумовые** — лежат среди объектов другого класса, 1NN по эталонам на них ошибается;
- **неинформативные** — правильно классифицируются эталонами, и их удаление ничего не меняет.

### 9.2. Алгоритм

Жадная стратегия добавления (слайд 26):

1. $\Omega :=$ по одному объекту от каждого класса.
2. Повторять:
   - найти $x \in X^L \setminus \Omega$, для которого $\mathrm{CCV}(\Omega \cup \lbrace x \rbrace) \to \min$;
   - $\Omega := \Omega \cup \lbrace x \rbrace$;
3. пока CCV уменьшается.

**Начальные объекты.** Лекция не уточняет, какие объекты брать на шаге 1. Берётся самый типичный представитель каждого класса — объект, ближайший к центру (среднему) своего класса.

**Остановка.** Алгоритм останавливается, как только лучший кандидат не уменьшает CCV. Остановка гарантирована: на каждом шаге CCV строго уменьшается, а разных подмножеств конечное число.

**Почему шум не попадает в эталоны.** Шумовой объект окружён объектами другого класса. Если его добавить, он станет ближайшим эталоном для этих соседей, и они начнут классифицироваться неверно. CCV вырастет, поэтому жадный алгоритм такой объект не выберет. Отдельный шаг отсева выбросов не нужен.

### 9.3. Быстрый пересчёт CCV (вывод)

На каждом шаге нужно вычислить $\mathrm{CCV}(\Omega \cup \lbrace x \rbrace)$ для каждого из примерно 700 кандидатов $x$. Пересчитывать всё с нуля слишком долго. Лекция (слайд 26) предлагает обновлять только вклады $T(x_i, \Omega)$, которые меняются при добавлении $x$.

Рассмотрим объект $x_i$ и его список ближайших эталонов $x_i^{(1 \mid \Omega)}, x_i^{(2 \mid \Omega)}, \dots$ с индикаторами ошибок $e_m = [y_i \ne y_i^{(m \mid \Omega)}]$. Добавим кандидата $x$. Пусть $p$ — число эталонов, которые ближе к $x_i$, чем $x$. Тогда $x$ встаёт в список на место $p + 1$:

- соседи на местах $m \le p$ остаются на месте и вносят $e_m R(m)$;
- сам $x$ на месте $p + 1$ вносит $[y_i \ne y_x] \, R(p + 1)$;
- соседи на местах $m > p$ сдвигаются на одно место вниз и вносят $e_m R(m + 1)$.

$$T(x_i, \Omega \cup \lbrace x \rbrace) = \underbrace{\sum_{m \le p} e_m R(m)}_{\text{префиксная сумма}} + \left[ y_i \ne y_x \right] R(p+1) + \underbrace{\sum_{m > p} e_m R(m+1)}_{\text{суффиксная сумма}}.$$

Префиксные и суффиксные суммы считаются один раз на шаге для каждого объекта (`np.cumsum`). После этого новый вклад для любой пары (объект, кандидат) вычисляется за $O(1)$ по позиции $p$. Если $x = x_i$, вклад не меняется: объект не может быть своим соседом.

Позиции $p$ для всех пар считаются векторно: сравнение расстояния до кандидата с 17 отсортированными расстояниями до эталонов. Весь отбор занимает около 3 секунд.

### 9.4. Результат

**Ход алгоритма** (`selection_history.png`):

| Число эталонов | 2 | 10 | 20 | 42 | 78 |
|---|---|---|---|---|---|
| $\mathrm{CCV}(\Omega)$ | 0.308 | 0.178 | 0.164 | 0.161 | 0.161 |

- Основной выигрыш приходится на первые 10–20 шагов, после 42 эталонов CCV уменьшается только в четвёртом знаке. Алгоритм остановился на **78 эталонах из 712 (11%)**.

**Профиль компактности эталонов** (оранжевая линия на `compactness_profile.png`): $\Pi(1, \Omega) = 0.159$, $\Pi(2, \Omega) = 0.166$, $\Pi(3, \Omega) = 0.178$, дальше профиль растёт до 0.37. ### 10.1. Матрица ошибок

Для бинарной задачи с положительным классом «Выжил» (1):

| | Предсказано: погиб | Предсказано: выжил |
|---|---|---|
| **Истинно: погиб** | TN (true negative) | FP (false positive) |
| **Истинно: выжил** | FN (false negative) | TP (true positive) |

### 10.2. Формулы

$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}, \qquad \text{Precision} = \frac{TP}{TP + FP}, \qquad \text{Recall} = \frac{TP}{TP + FN},$$

$$F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}.$$

- **Precision** (точность): какая доля объявленных выжившими действительно выжила.
- **Recall** (полнота): какую долю реально выживших модель нашла.
- **F1** — их гармоническое среднее. Оно мало, если мала хотя бы одна из величин.

**Упрощение F1 (вывод).** Подставим определения:

$$F_1 = \frac{2 \cdot \frac{TP}{TP+FP} \cdot \frac{TP}{TP+FN}}{\frac{TP}{TP+FP} + \frac{TP}{TP+FN}} = \frac{2\,TP^2}{TP(TP+FN) + TP(TP+FP)} = \frac{2\,TP}{2\,TP + FP + FN}.$$

| Окно Парзена + эталоны | 105 | 5 | 39 | 30 | $\frac{135}{179} = 0.754$ | $\frac{30}{35} = 0.857$ | $\frac{30}{69} = 0.435$ | $\frac{60}{104} = 0.577$ |

### 10.4. Зачем F1, если есть accuracy

Классы несбалансированы: 61.5% погибших. Модель, которая всем отвечает «погиб», имеет accuracy 0.615, но не находит ни одного выжившего (Recall = 0, F1 = 0). F1 по классу «Выжил» показывает, насколько хорошо модель находит меньший класс.

У большинства моделей precision выше recall: модель редко ошибочно объявляет выжившим, но пропускает часть реально выживших. Это следствие дисбаланса: в зоне перекрытия у объекта больше соседей из класса «Погиб» просто потому, что этот класс больше. Сильнее всего эффект у окна Парзена на эталонах, где дисбаланс среди эталонов ещё больше (61 против 17).

## 11. Визуализация: PCA

Код: `plot_references` в `source/visualization.py`.

Объекты 8-мерные, а график двумерный. Для проекции используется **метод главных компонент** (PCA): данные проецируются на два направления, вдоль которых разброс (дисперсия) максимален. Математически это собственные векторы ковариационной матрицы $\Sigma = \frac{1}{\ell} \tilde{X}^\top \tilde{X}$ с двумя наибольшими собственными значениями $\lambda_1 \ge \lambda_2$. Доля объяснённой дисперсии компоненты $j$ равна $\lambda_j / \sum_i \lambda_i$.

У нас PC1 объясняет 27% дисперсии, PC2 — 22%, вместе около половины. Поэтому график — приближённая картина. Объекты, которые на проекции выглядят перемешанными, в 8-мерном пространстве могут быть разделены. PCA используется **только для рисунка**: классификатор работает с исходными 8 признаками.
